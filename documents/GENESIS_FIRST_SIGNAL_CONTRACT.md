# First Signal / Genesis integration contract

Decision A: First Signal remains the visual creation shell; Genesis owns newly approved identity and activation. Quick creation requires no inference. Deeper discovery is optional and continues the same Genesis draft. This work does not execute installers, sign releases, generate real credentials, or accept native installed behavior.

## State transitions

1. **Local visual draft:** name and purpose are proposed identity details; appearance and temperament are presentation choices. Nothing is allocated. Imported text remains a visible proposal.
2. **Explicit review:** the existing Review step states that the chosen name and purpose become identity; appearance remains presentation. Save a client UUID, exact Hive address, and original input before sending a keyed Genesis session request.
3. **Stored Genesis draft:** keyed retries return the same session without replacing edits. Quick activation and optional deeper discovery use this exact session. Failed/unknown requests keep the journal and require an explicit check/retry.
4. **Identity reservation:** Genesis uses the existing durable creation receipt keyed by session UUID. A reserved or completed receipt determines the Entity UUID before the session link is saved. A retry after interrupted linking must recover that UUID, including after restart; unavailable receipts fail closed.
5. **Linked activation:** persist the Entity link before birth/media work. Existing linked Genesis sessions keep their UUID. A ready session returns unchanged. Existing Entities continue their current conversation; no new awakening is inserted on ordinary reopen.
6. **Visual save and reveal:** save presentation against the confirmed Entity, retaining approved name/purpose for display. A failure leaves the same journal/session recoverable. Reveal and first conversation use the existing shared Runtime surface and exact Entity guard.
7. **Legacy return:** old presentation-only briefs and unfinished First Signal receipts retain their existing recovery path. They are never automatically seeded into Genesis, re-keyed, reallocated, or treated as approved narrative. Existing beta Genesis sessions remain resumable.

## Regression contract

- Repeated session creation returns one exact session; changed original input is rejected and current reviewed edits survive retries.
- Interrupted allocation/link persistence, process reconstruction, and duplicate retries return one UUID; deleted/unavailable receipts do not allocate replacements.
- Previously linked sessions and old presentation-only Entities do not allocate or receive a new awakening on return.
- Quick creation makes no model call; deeper discovery retains the same session and requires explicit proposal approval.
- Journal storage failure prevents dispatch; uncertain outcomes preserve the same key and pinned Hive; late responses do not open another Entity.
- Genesis JSON/assets carry verified native profile/process ownership alongside the existing local capability. No fallback to another profile.
- Profile isolation, whole-profile recovery, conversation session restoration, optional first tasks, honest Stop/error/recheck, and static Windows runtime checks retain regression coverage.
- An allocated Genesis Entity cannot use generic birth or open its first conversation before awakening completes, including interruption before the session link is saved. Existing awakened Entities remain reopenable during later draft refinements.
- Presentation excerpts respect sidecar limits without changing canonical narrative. All accepted quick-creation Unicode names must survive canonical validation; older valid names remain readable.

Validation records must distinguish source/unit/fixture evidence from real model, native GUI, credentials, media billing, installer and release acceptance. The prior branches' evidence does not transfer to new integrated bytes.
