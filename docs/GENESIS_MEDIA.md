# Genesis media providers and operations

Genesis can awaken an Entity before portraits or films finish. Its private media queue runs in Hive independently of conversation and activation. The free animated emergence is always available.

## Built-in adapters

Portrait generation uses the existing Hive `openai` credential and the direct Images API with `gpt-image-2`, medium quality, PNG output and 1024 × 1024 composition. One to four candidates can be requested. Discovery of a key does not prove paid model access: provider failures remain visible as failed media jobs and do not block awakening.

Film generation uses the existing Hive `runway` credential and Runway `gen4_turbo`. The selected, explicitly approved portrait is submitted as the exact PNG data URI, with a 960 × 960 output and a chosen 5 or 10 second duration. There is no separate independent character prompt. The motion prompt describes emergence and asks the model to finish in the reference composition. Runway accepts the image as its starting reference; the end frame is not guaranteed. Users must compare a film to its reference and approve identity consistency before it becomes canonical. The frontend transitions from the film to the persistent portrait.

Runway API requests use `https://api.dev.runwayml.com`, `X-Runway-Version: 2024-11-06`, `POST /v1/image_to_video`, `GET /v1/tasks/:id`, and `DELETE /v1/tasks/:id`. Status polling is no more frequent than every six seconds. Input is bounded to 5,000,000 bytes after data URI encoding. Film direction and preset together are limited to 700 UTF-16 code units, leaving room inside the provider's 1,000-unit prompt limit. Oversized portraits are rejected before submission.

Outputs are downloaded immediately into private Hive storage. Only HTTPS provider/CDN hosts ending in `.cloudfront.net`, `.runwayml.com`, or `.runway.com` are accepted. Credentials, fragments and nonstandard ports are rejected. Every resolved address must be public, and those addresses are pinned for the request. Redirects and proxy inheritance are disabled for downloads, and the Runway API key is never forwarded to a storage host. A film is capped at 64 MiB and must have an MP4 signature. Signed provider URLs never reach the frontend or persisted job record.

Sora is deliberately not implemented: the OpenAI deprecations page lists the Videos API and Sora 2 shutdown on September 24, 2026, with no replacement. This was checked on October 17, 2026.

## Costs and consent

Every new render, including a paid retry or regeneration, requires the user to confirm its displayed budget reservation. Defaults are $0.25 per portrait candidate, $2 per film, a $10 daily budget and 20 jobs per household per UTC day. At most three jobs may be queued or running concurrently. Budget checks and reservations are serialized in Hive, and a repeated idempotency key returns the existing job without another reservation or provider submission. Reusing a key for a different request is rejected.

Reservations are conservative local admission controls, not provider invoices or guaranteed billing caps. GPT Image 2's documentation lists a medium 1024 × 1024 output estimate of $0.053 plus prompt input tokens. Runway lists Gen-4 Turbo at 5 credits per second and $0.01 per credit, or $0.25/$0.50 for 5/10 seconds before applicable tax. These references were verified on October 17, 2026; providers can change pricing. Provider project billing limits remain the authoritative spending control.

Cancelling, failure, or deleting a draft does not refund the local reservation. A provider may already have charged a submitted request. This conservative accounting prevents deletion or failed jobs from bypassing the daily budget.

## Durability, ownership and deletion

Hive's embedded database stores `generation_jobs`, `entity_assets` and the `genesis_media_v1` migration marker. Generated bytes live under the profile's `genesis_assets` directory, with UUID filenames, atomic writes, content hashes and restrictive Unix permissions. The enclosing local profile supplies Windows account permissions. The HTTP endpoints require the same desktop capability and household/session ownership as Genesis itself. All media responses are private and `no-store`.

Queued work survives restart. Submitted asynchronous jobs resume by their provider task ID. A crash during an uncertain submission is marked `interrupted`; Hive never silently repeats a potentially billable POST. A user can explicitly confirm a retry after reviewing provider usage. Completed asset writes are reconciled if a crash occurred before the job completion record. A temporary polling failure resumes the original task rather than starting a new paid render. A definitive provider failure can be retried as a new, separately confirmed render.

Portrait candidates retain independent versions. Switching the canonical portrait clears a selected film that was based on a different portrait. Film approval checks that its reference is still the current canonical portrait. Deleting a portrait clears affected canonical film pointers, and deleted asset pointers are removed from undo snapshots. A running film must be stopped before its portrait reference can be deleted. Media created before awakening is attached to the allocated Entity; approvals after awakening update the media fields in its permanent `genesis.json` without applying other unfinished draft edits.

Deleting a draft cancels its jobs, clears stored prompts and motion descriptions, and removes local generated files and asset records. Minimal job accounting tombstones remain to enforce quotas. Provider-side cancellation/deletion is attempted when a provider task ID exists; it follows that provider's own retention policy and is not a promise of immediate remote erasure. Individual asset deletion removes local bytes. No voice recordings pass through this media subsystem.

Optional Genesis record retention applies the same deletion process automatically after 1–3650 days without a saved change. Records are kept until manually deleted by default. Hive checks expiry on startup and once per minute, skips busy records and rechecks their current policy under the session lock. Expiry removes the record's local media and clears permanent visual pointers while preserving the awakened Entity and its actual chat history. It does not bypass quota tombstones or guarantee remote provider erasure.

## Operator overrides

These settings are optional and read when Hive starts. No model output, imported document, or media request can set them.

| Variable | Default / allowed values |
| --- | --- |
| `ABIGAIL_GENESIS_IMAGE_MODEL` | `gpt-image-2`; also accepts `gpt-image-2-2026-04-21` |
| `ABIGAIL_GENESIS_VIDEO_PROVIDER` | `runway`; also `disabled` or `reference-video-gateway` |
| `ABIGAIL_GENESIS_PORTRAIT_RESERVATION_USD` | `0.25` per candidate |
| `ABIGAIL_GENESIS_VIDEO_RESERVATION_USD` | `2.00` per film |
| `ABIGAIL_GENESIS_DAILY_BUDGET_USD` | `10.00` |
| `ABIGAIL_GENESIS_DAILY_JOB_LIMIT` | `20`, allowed 1–100 |

Invalid settings disable paid adapters without preventing Hive from launching. Credentials remain in the existing encrypted Hive secrets vault. This implementation does not create keys, sign users in, or extract CLI account tokens.

## Optional local reference-video gateway

For another provider, set `ABIGAIL_GENESIS_VIDEO_URL=http://127.0.0.1:PORT` (or literal IPv6 loopback) and `ABIGAIL_GENESIS_VIDEO_MODEL=MODEL`. A configured local URL selects the gateway unless `ABIGAIL_GENESIS_VIDEO_PROVIDER` overrides it. Hostnames, credentials, paths, queries and remote addresses are rejected. The gateway owns its upstream provider integration, credential storage and pricing. It must actually support the advertised 4/8/12 second durations; the built-in Runway adapter advertises 5/10 instead.

The contract is:

* `POST /jobs` with an `Idempotency-Key` header and JSON `{model, prompt, seconds, reference_png_base64, reference_asset_id, identity_constraints}`. It must preserve the supplied image identity and honor idempotency.
* `GET /jobs/:id` returns progress or completed bytes.
* `DELETE /jobs/:id` cancels an active render or deletes provider output; return success or 404 for an already removed task.
* Pending response: `{ "id": "provider-task-1", "status": "running", "progress": 40 }`; `queued` is also accepted. IDs are 1–100 ASCII alphanumeric, underscore or hyphen characters.
* Complete response: `{ "status": "completed", "video_base64": "…", "mime_type": "video/mp4" }`. WebM is also accepted. URLs are not accepted in place of bytes. Responses are bounded to 96 MiB; decoded films to 64 MiB.
* Failure response: `{ "status": "failed" }` or `{ "status": "cancelled" }`. Provider error bodies are not exposed to users or logs.

The gateway is an extension seam; the Runway adapter works directly and does not require this extra service.

## Verification scope and sources

Unit and deterministic provider fixtures cover ownership, idempotency, explicit confirmation, concurrent budget reservations, retained quotas after deletion, approved reference coupling, identity review, restart/resume, crash reconciliation, PNG validation, transport parameters, status normalization and SSRF guards. No live billed image or film generation was run as part of implementation. Account access, actual visual quality and identity consistency still require a separately consented provider acceptance run.
